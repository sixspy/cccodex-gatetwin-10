# 闸对

中文名：**闸对** · 前缀 `gatetwin` · 端口 **6500 / 11500**

## 骨架

**刷卡点装载 → 同卡进站出站成对物化 → 缺腿/异向/超时旁路 → 行程账与刷卡点互证**

皮：地铁/公交闸机刷卡。去皮是 **OD 成对管道 + 开腿态 + 旁路 + 行程贯验**，不是票务售票 CRUD、不是乘车码业务页、不是日结封账。

## 冒烟

```bash
docker compose up -d --build
# http://127.0.0.1:6500
# 刷卡流 → 灌「成对样例」→ 看开腿账/行程账 → 再灌「缺腿超时样例」「出站孤儿样例」→ 行程贯验
```

## 主链对象

| 对象 | 作用 |
| --- | --- |
| 刷卡点 | 带卡号/站点/方向/事件时的进出闸事件 |
| 开腿账 | 已进站尚未出站的在途开腿 |
| 行程账 | 进站+出站成对后的正式行程 |
| 旁路匣 | 缺腿超时 / 出站孤儿 / 重复进站等 |
| 行程贯验 | 成对刷卡 ↔ 行程笔数 ↔ 旁路命运互证 |
| 行程键幂等 | 进出业务对指纹去重（口径乙），防双行程/幽灵行程，见下 |

## 行程键幂等（已落地）

**全局唯一口径：乙 —— 行程键（进站事件编号+出站事件编号）所代表的进出业务对幂等。**
不采用「事件编号全局幂等承载行程唯一」的甲口径。

- 幂等指纹 = 哈希（卡号 + 进站站点键 + 出站站点键 + 进站事件时 + 出站事件时），
  **与事件编号解耦**。复制进出业务对、只改事件编号再装载 → 同指纹 → 挡下第二行程。
- 两道闸：① 事件编号已存在 → 整事件跳过（同批重放）；
  ② 出站成对前按业务对指纹探测，命中 → 新进站+新出站整体进旁路匣（原因`行程幂等重复`），不写第二行程。
- **探测与插入同成败**：整批在 `BEGIN IMMEDIATE` 单事务内完成；`行程账.幂等指纹` 唯一索引兜底，
  写闸用 `INSERT OR IGNORE` + 回读；并发双装胜者全成、败者重放收敛，异常整批 rollback，无半截幽灵行程。
- 只读接口：`GET /api/行程幂等/探测`（探测键/命中行程或跳过/幽灵行程计数/valid）、
  `GET /api/行程幂等/态`（拦截计数/幽灵/重复指纹组/valid）；贯验与总览协同校验不变量。
